# Run Commit

`run.commit` is the sole transaction boundary between A06 staging and a published run. It does not generate artifacts, execute DAG nodes, diagnose results, synthesize repository-iteration provenance, or update A08 indexes.

The administrative CLI is `code-intel run commit --source-root <A09-artifact-root> --authority-root <publication-root> --manifest-ref <artifact-ref.json> --final-name <name>`. It revalidates the source A09 manifest and refs, copies the already-authorized bytes through a fresh A06 owned staging set, rewrites the terminal manifest to the resulting content-addressed Artifact Refs, and then invokes the publication transaction. The PowerShell flags `-RunCommitSourceRoot`, `-RunCommitAuthorityRoot`, `-RunCommitManifestRef`, and `-RunCommitFinalName` are compatibility forwarding only.

For a fresh authoritative repository iteration, use `code-intel run execute --repo <repo-root> --out <staging-root> --authority-root <artifact-root> --final-name <name>`. Its private Rust controller creates the versioned `repository.iteration` provenance Artifact Ref before invoking Run Commit, validates the committed publication, rebuilds the Rust A08 completed-only index, and publishes that index. A direct administrative `run commit` never invents this provenance, so a snapshot-only or governance manifest cannot become repository-query authority merely by being committed.

Before promotion it reopens and validates the A09 terminal run manifest, every referenced A06 artifact, registered schema/type, SHA-256 digest, and consumed snapshot identity. The staged directory is promoted with same-authority, atomic no-replace rename semantics and its parent directory is synchronized. `run-complete.json` is created only after promotion and directory synchronization, published with a second atomic no-replace rename, synchronized, then reread. The marker binds the run identity, repository snapshot, manifest path, and manifest digest.

Failures before promotion leave A06 ownership cleanup intact. Failures after promotion leave an uncommitted, recoverable directory; `recover` repeats full validation and synchronizes the promoted directory entry before publishing a marker. A post-marker verification failure removes a marker only when both its stable file identity and bytes still match the file published by that attempt. Existing destination directories and competing marker files are never replaced or recursively deleted.

Directories without a valid marker, including legacy timestamp reports and the retired `{generatedAt,report,reportSha256}` marker shape, are not committed authority. A08 is implemented in Rust: `code-intel artifact index` accepts only completed A07 publications with exactly one verified, succeeded `repository.iteration` provenance ref bound to the manifest, marker, repository directory, and publication directory. `legacy/update-code-intel-index.ps1` normally forwards to that implementation; its explicit legacy compatibility traversal is advisory and cannot establish repository authority.
